4. 风险与对策

级别风险证据对策
P0进 Kokiri 丢设备（残留 1/5 概率）vk_memory.cpp:2690-2696：B390 上归还 retired imports 必丢，不归还仍 5 次 1 次丢（issue 17）先按默认（不归还）跑；丢设备时用 RX_VK_KEEP_RETIRED/RX_VK_WB_DIFF/RX_VK_MIRROR/RX_VK_VRAM_MB 做开关矩阵定位
P0UMA 内存耗尽纹理 2560 + 影子 512 + 游戏约 10 GB，32 GB 余量不宽先原样跑，OOM 再压 2048/256，看 system_heap_usage 日志
P1首帧卡顿Intel 管线串行编译构建期预编译 shader（不给 --no-prepare-shaders）
P1EQ 偏置 64 是否适合 Xe3该值未在 B390 单独验证视觉验收地面/水/雾，扫 RX_VK_EQ_BIAS=0/32/64/128
P2DLSS 不可用（NGX 只认 NVIDIA，FSR 4 需 AMD DLL）—先用内置 FSR 3.1；把本项目的 Intel NR 接进 DLSS 槽位是后续独立里程碑

6.1 花屏与驱动崩溃（2026-11-11 晚，已复现）

现象证据性质
花屏 / 忽黑忽白内置 RX_VK_SHOTS 读回真实呈现图：第 300 帧全黑、600 帧只有一块 UI 面板、900 帧全黑、1200 帧纯白（luma 246）。同一时刻每帧 612 次 draw、118 个 pass、11800 条 barrier，帧率 12.9 fps，最慢一帧 4174 ms，680.3 draws left out (not ready)管线按需编译把每帧拖到秒级，呈现缓冲反复落在未画完的帧上
卡退CRASH: exception 0xc0000005 (read 0x190, guest 0xfffff00000000190) at igvk64.dll+0x79ddf3，回溯 igvk64.dll×5 → hookshot_vk.dll+0x1f8933 → ucrtbase → KERNEL32，发生在构建管线的后台线程里Intel 驱动内部空指针，不是模拟器代码崩，属上游 known issue（Intel 卡 "black screen or crash"）
前一次（无 NOOPT）submit 77254 failed (-4) → the GPU device was lost，丢失前一批 11 个 compute dispatch 连续提交；此前 slow submit: 15-18 ms 持续累积Windows TDR（默认 2 s）先把 GPU 判死
转译缺口10 个 compute 程序 native op 0xb66 无法 lower（040a7b66 30800809 … / 10127b66 30800813 …，word1 bit28=0，与现有 lower 规则要求的 Bits(60,1)=1 不符），每帧 12 个 dispatch 被跳过；另有 a network left out on this card 使一批程序不转译需在 lower_to_maxwell.h 补 TLD 变体
已固化的启动参数（写在游戏目录 hookshot_env.txt）：RX_VK_NO_WARM=1、RX_VK_PRECOMPILE_COMPUTES=none、RX_VK_PRECOMPILE_STALL_S=10、RX_VK_MESH_NOCULL=2c56dc1006942f74（readme 里针对 "剔除 pass 跑数秒导致卡死" 的官方绕过）。注意：实际启动时仍以命令行环境变量为准，直接双击可能重新触发 12,389 条管线预编译（约 100 分钟）。

6.2 卡死定位与绕过（2026-11-11 02:1x）

后端自带 RX_VK_CHECKPOINTS 的 GPU 标记环，设备丢失时会把标记序列打出来。实测丢设备瞬间的转储是：

vk:   stage 0x2000: marker 65209 (dispatch of program ab7699ee7f536755, frame 778)
vk:     before: dispatch of program 48590e0b8589d6ca   ×5（都没等到 after）
vk: FATAL: the GPU device was lost (VK_ERROR_DEVICE_LOST)

即 frame 778 进入林区那一串 compute 里，ab7699ee7f536755 的 dispatch 之后 GPU 再没有前进。查源码 vk_draw.cpp:5503 有同一现象的记录：issue 817，Kokiri 林区/德库树里一批 task/mesh 程序共享 task shader 2c56dc1006942f74，在里面跑一个几秒级的剔除循环，直到内核判死 GPU；RX_VK_SKIP_CODE=2c56dc1006942f74 是项目自己的绕法（代价是这批程序画的模型也一起没了）。

另外把 Windows TDR 从默认 2 s 放宽到 60 s（HKLM\SYSTEM\CurrentControlSet\Control\GraphicsDrivers 的 TdrDelay/TdrDdiDelay=60，重启生效），用来看清这类"几秒级 pass"到底是被 TDR 误杀还是真的死循环。

判断画面好坏别靠抓窗口（会被 IDE 遮挡），用后端自己的 RX_VK_SHOTS=<dir> + RX_VK_SHOT_EVERY 读回真实呈现图。本机实测：菜单帧结构正常（neighbour difference 2.5-2.8，saturation 0.54-0.60），进入场景前后会出现整帧纯黑与整帧纯白（luma 226）——纯白那张是横向渐变，属过场淡入淡出，不是花屏；真正的花屏要看进场景之后的帧。
